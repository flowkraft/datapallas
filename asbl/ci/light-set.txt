# asbl/ci/light-set.txt: THE LIGHT SET, the tests a release runs on the lanes where it does not run the full suite.
#
# What it is: one list for the four lanes that run a light set. They are:
#   - the Docker release's Linux proof on docker-server (asbl/ci/jenkins/release-docker.sh, DOCKER RELEASE STEP 3/6);
#   - windows-vm-docker (its DOCKER RELEASE STEP 4/6);
#   - windows-vm-server (step 1, lane 4);
#   - windows-vm-electron (step 3's RELEASE STEP 2/4, recorded as step 1's lane 3).
# The release record calls such a run "light" (asbl/ci/release-state.sh record-step1).
# How it is read, step by step (asbl/ci/dp-ci.sh light_set_filters <lane>):
#   1. Every line that is not blank or a comment is an entry: zone | lanes | spec file | test title.
#   2. A lane keeps the entries whose lanes field is "all" or its own group: server is docker-server, web,
#      windows-vm-docker and windows-vm-server; electron is windows-vm-electron (and the Linux electron target).
#   3. The spec file (under frend/reporting/e2e/) must be there. An empty title takes the whole file. A title takes that
#      one test: the test's own title, exactly, without its describe titles.
#   4. The entries become the two filters every lane already hands to playwright.config.ts: E2E_SPEC (the files) and
#      E2E_GREP (the tests). A lane is asked for the set with E2E_SPEC=light; windows-vm-docker and windows-vm-server
#      also take it when neither E2E_SPEC nor E2E_GREP is given, as before.
# Inputs: this file alone, with no "|" inside a field. No defaults.
# Dry run: print each lane's entries and its two filters, running nothing:
#   bash asbl/ci/dp-ci.sh light-set                      (the four lanes)
#   bash asbl/ci/dp-ci.sh light-set windows-vm-docker    (one lane)
# To see the tests themselves without running them, use Playwright's list (in frend/reporting, with that lane's two
# filters):
#   TEST_ENV=web E2E_SPEC='<E2E_SPEC>' E2E_GREP='<E2E_GREP>' npx playwright test -c e2e/playwright.config.ts e2e/ --list
# It never runs anything. A lane never runs any set but this one: a bad entry stops the lane before its first test.
# Callers: dp-ci.sh e2e (E2E_TARGET=docker-server E2E_SPEC=light), dp-ci.sh win e2e (E2E_SPEC=light), dp-ci.sh win
# docker-e2e and win server-e2e. Through those: release-docker.sh, win-e2e.sh release, release-rerun.sh and the step 1 job.
#
# Lane limits:
#   - auth-authorization-server is server only (the Electron flow serves no web UI). Taken whole, it runs alone, because it
#     changes accounts, roles and, last, burst's password.
#   - let-me-update-migrate-configuration is Electron only.
#   - The Electron-only tests of auth-authorization-desktop skip themselves on the server lanes.
#
# zone | lanes | spec file | test title (empty = the whole file)
#
